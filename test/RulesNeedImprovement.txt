BR53458 — NEEDS IMPROVEMENT (rules/07-player-interaction.md:146)
Note: The rule describes a source-code mechanism ("monsters flagged to be omitted from the sidebar") rather than in-game terminology, and it overstates the behavior. The automatic sidebar listing does skip such creatures (IO.c:3800-3802), but a creature the player points the cursor at is still listed, because the focused-entity path adds it to the list regardless of the trait (IO.c:3718-3724, IO.c:3784-3791) and the sidebar is redrawn with the focus first when the focused entity does not make it onto the screen (IO.c:3906-3909). So "never listed there" is not true, and the citation only covers the automatic listing. The same behavior is already described in in-game terms by BR48675. Suggested rewrite: "A creature that is not listed in the sidebar is left out of the sidebar when the list is drawn, but it does show up there while the player points the cursor at it."

BR47597 — NEEDS IMPROVEMENT (rules/09-monsters-bestiary.md:10)
Note: The rule bundles a second, counterfactual behavior with the main one: "(and, for a player, would not force item-dropping)". The player is never immune to water (the player's creature entry grants only the male/female traits, Globals.c:1027-1028, and no code path grants the water immunity to the player), so that clause describes a situation that never occurs in game and is therefore not an observable behavior. The cited lines (Rogue.h:2077, Monsters.c:1395-1398) do not implement the item-dropping exemption either; the deep-water item loss it alludes to is Time.c:474-477. Suggested rewrite: keep only the observable behavior — "Water does not slow the creature down and does not deter it: it crosses deep water as readily as dry ground" — and, if the deep-water item loss is worth a rule of its own, write it separately citing Time.c:474-477.
